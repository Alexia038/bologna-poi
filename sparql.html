SPARQL Queries

In questa sezione vengono riportati alcuni esempi di query SPARQL utilizzate per l'esplorazione dell'ontologia nazionale POI-AP_IT.

Esplorazione generale dell'ontologia POI-AP_IT

La seguente query è stata utilizzata per ottenere una vista generale delle risorse appartenenti all'ontologia POI-AP_IT, interrogando l'endpoint nazionale e filtrando i soggetti sul namespace dell'ontologia:

PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>

SELECT DISTINCT ?s ?p ?o
WHERE {
  ?s ?p ?o .
  FILTER(STRSTARTS(STR(?s), "https://w3id.org/italia/onto/POI"))
}
LIMIT 100

Questa query utilizza DISTINCT per evitare duplicati e FILTER per restringere il dominio alle sole risorse dell'ontologia POI-AP_IT, restituendo un campione delle triple disponibili (limitato a 100 risultati).

Individuazione delle classi disponibili

Per identificare le classi definite dall'ontologia POI-AP_IT e raccoglierne informazioni descrittive (etichette e commenti) è stata utilizzata la seguente query:

PREFIX owl:  <http://www.w3.org/2002/07/owl#>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>

SELECT DISTINCT ?class ?label ?comment
WHERE {
  ?class a owl:Class .

  OPTIONAL { ?class rdfs:label ?label . }
  OPTIONAL { ?class rdfs:comment ?comment . }

  FILTER(STRSTARTS(STR(?class), "https://w3id.org/italia/onto/POI/"))
}
ORDER BY ?class
LIMIT 100

In questo caso, OPTIONAL viene utilizzato per recuperare etichette e commenti quando disponibili, senza escludere le classi che ne sono prive, mentre ORDER BY consente di ordinare le classi per IRI, facilitandone la consultazione. La query ha permesso di identificare le classi riutilizzabili nel progetto e di documentarne il significato semantico prima di proporre un'estensione locale.

Figura 2: Risultati della query per l'individuazione delle classi disponibili in POI-AP_IT.

Individuazione delle proprietà riutilizzabili

Per analizzare le proprietà definite in POI-AP_IT (sia owl:ObjectProperty sia owl:DatatypeProperty) è stata impiegata la seguente query:

PREFIX owl:  <http://www.w3.org/2002/07/owl#>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>

SELECT DISTINCT ?property ?label ?comment ?domain ?range ?type
WHERE {
  ?property a ?type .

  FILTER(?type IN (owl:ObjectProperty, owl:DatatypeProperty))
  FILTER(STRSTARTS(STR(?property), "https://w3id.org/italia/onto/POI/"))

  OPTIONAL { ?property rdfs:label ?label . }
  OPTIONAL { ?property rdfs:comment ?comment . }
  OPTIONAL { ?property rdfs:domain ?domain . }
  OPTIONAL { ?property rdfs:range ?range . }
}
ORDER BY ?property
LIMIT 100

FILTER viene utilizzato sia per filtrare il tipo della proprietà (ObjectProperty o DatatypeProperty), sia per delimitare il namespace di interesse, mentre le clausole OPTIONAL consentono di recuperare metadati utili per il riuso (dominio, range, etichette, commenti). Questa query è stata fondamentale per selezionare le proprietà da riutilizzare nel mapping dei dataset bolognesi, evitando la definizione ridondante di proprietà locali.

Figura 3: Risultati della query per l'individuazione delle proprietà riutilizzabili di POI-AP_IT.

Ricerca di concetti potenzialmente rilevanti per Bologna

Per verificare l'eventuale presenza, nell'ontologia nazionale, di concetti relativi ai servizi urbani bolognesi o ad elementi di arredo urbano, è stata definita una query che combina più pattern e fa uso di REGEX:

PREFIX owl:  <http://www.w3.org/2002/07/owl#>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>
PREFIX dct:  <http://purl.org/dc/terms/>

SELECT DISTINCT ?resource ?type ?label ?comment ?description
WHERE {
  {
    ?resource a owl:Class .
    BIND("Class" AS ?type)
  }
  UNION
  {
    ?resource a owl:ObjectProperty .
    BIND("ObjectProperty" AS ?type)
  }
  UNION
  {
    ?resource a owl:DatatypeProperty .
    BIND("DatatypeProperty" AS ?type)
  }

  OPTIONAL { ?resource rdfs:label ?label . }
  OPTIONAL { ?resource rdfs:comment ?comment . }
  OPTIONAL { ?resource dct:description ?description . }

  FILTER(STRSTARTS(STR(?resource), "https://w3id.org/italia/onto/POI/"))

  FILTER(
    REGEX(STR(?resource),    "Bologna|TPER|bench|panchina|toilet|bagno|parking|parcheggio|portico|bus stop|fermata|arredo", "i")
    ||
    REGEX(STR(?label),       "Bologna|TPER|bench|panchina|toilet|bagno|parking|parcheggio|portico|bus stop|fermata|arredo", "i")
    ||
    REGEX(STR(?comment),     "Bologna|TPER|bench|panchina|toilet|bagno|parking|parcheggio|portico|bus stop|fermata|arredo", "i")
    ||
    REGEX(STR(?description), "Bologna|TPER|bench|panchina|toilet|bagno|parking|parcheggio|portico|bus stop|fermata|arredo", "i")
  )
}
ORDER BY ?type ?resource
LIMIT 100

La query utilizza UNION per considerare contemporaneamente classi, object property e datatype property, e filtra i risultati tramite più espressioni regolari su IRI, etichette, commenti e descrizioni, con l'obiettivo di intercettare qualsiasi risorsa che contenga riferimenti a Bologna, TPER, arredo urbano, bagni, parcheggi o portici. I risultati hanno confermato l'assenza di un supporto specifico per molte delle categorie urbane di interesse, motivando la progettazione di un'estensione ontologica locale.
