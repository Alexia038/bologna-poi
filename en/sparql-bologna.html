Validation and Querying of the Knowledge Graph

After generating the RDF triples from the integrated dataset of urban points of interest in Bologna, the instances were imported into the local ontology to build a single Knowledge Graph containing both the ontological schema and the data.

The validation of the graph was performed using the HermiT reasoner, which allowed for verifying the semantic consistency of the classes, properties, and generated triples. Once the validation phase was completed, the Knowledge Graph was queried via SPARQL queries using Google Colab and the Python rdflib library.

The queries made it possible to explore both the structure of the ontology and the instances generated from the original data, verifying the correct representation of elements such as TPER bus stops, urban furniture, porticoes, parking lots, and public services.

2. SPARQL Query for the Search of Relevant Concepts for Bologna

Execution of the query via the rdflib library to explore the classes, object properties, and datatype properties present in the local ontology.

query = """
PREFIX owl:  <http://www.w3.org/2002/07/owl#>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>
PREFIX dct:  <http://purl.org/dc/terms/>

SELECT DISTINCT ?resource ?type ?label ?comment ?description
WHERE {
  {
    ?resource a owl:Class .
    BIND("Class" AS ?type)
  }
  UNION
  {
    ?resource a owl:ObjectProperty .
    BIND("ObjectProperty" AS ?type)
  }
  UNION
  {
    ?resource a owl:DatatypeProperty .
    BIND("DatatypeProperty" AS ?type)
  }

  OPTIONAL { ?resource rdfs:label ?label . }
  OPTIONAL { ?resource rdfs:comment ?comment . }
  OPTIONAL { ?resource dct:description ?description . }

  FILTER(STRSTARTS(STR(?resource), "http://dati.comune.bologna.it/ontology/bologna-poi#"))
}
ORDER BY ?type ?resource
LIMIT 100
"""

for row in g.query(query):
    print("Risorsa:", row.resource)
    print("Tipo:", row.type)
    print("Label:", row.label)
    print("Commento:", row.comment)
    print("---")

3. SPARQL Query on Benches

Execution of the query via rdflib to extract detailed information on benches (instances of bo:Bench), including the district, material, and description.

query = """
PREFIX bo: <http://dati.comune.bologna.it/ontology/bologna-poi#>
PREFIX l0: <https://w3id.org/italia/onto/l0/>

SELECT ?bench ?district ?material ?description
WHERE {
  ?bench a bo:Bench ;
         bo:hasDistrict ?district ;
         bo:hasMaterial ?material ;
         l0:description ?description .
}
LIMIT 20
"""

for row in g.query(query):
    print(row.bench, row.district, row.material, row.description)

4. SPARQL Query for Porticoes

Execution of the query via rdflib to extract instances of porticoes (bo:Portico), including the textual description and the associated complex spatial geometry (GeoShape).

query = """
PREFIX bo: <http://dati.comune.bologna.it/ontology/bologna-poi#>
PREFIX l0: <https://w3id.org/italia/onto/l0/>

SELECT ?portico ?description ?shape
WHERE {
  ?portico a bo:Portico .

  OPTIONAL { ?portico l0:description ?description . }
  OPTIONAL { ?portico bo:hasGeoShape ?shape . }
}
LIMIT 20
"""

for row in g.query(query):
    print("Portico:", row.portico)
    print("Descrizione:", row.description)
    print("GeoShape:", str(row.shape)[:120] if row.shape else "")
    print("---")

5. SPARQL Query for All TPER Bus Stops with Name and Line

Execution of the query via rdflib to extract TPER bus stops (instances of bo:BusStop), including the stop name and the corresponding line.

query = """
PREFIX bo: <http://dati.comune.bologna.it/ontology/bologna-poi#>

SELECT ?stop ?name ?line
WHERE {
    ?stop a bo:BusStop ;
          bo:hasBusStopName ?name ;
          bo:hasBusLine ?line .
}
LIMIT 20
"""

for row in g.query(query):
    print("Fermata:", row.name)
    print("Linea:", row.line)
    print("URI:", row.stop)
    print("-----")
