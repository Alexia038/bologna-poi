LLM Experiments & Prompting Techniques

Based on the integrated CSV file and the Turtle file of the local ontology created in Protégé, an automatic generation phase of RDF triples using Large Language Models (LLMs) was designed. In this phase, two models were compared, Gemini Pro and ChatGPT Plus, both tested through three different prompting techniques: zero-shot, few-shot, and zero-shot chain-of-thought.

Technique 1 — Zero-Shot Prompting

In the zero-shot technique, the model is provided only with the task instruction, without any examples of the expected output. The prompt used is the following:

Generate valid RDF triples in Turtle format to describe the urban points of interest extracted from the dataset df_POI.csv, using our ontology.

Technique 2 — Few-Shot Prompting

In the few-shot technique, along with the task instruction, the model is provided with some concrete examples of the expected RDF triples in order to guide its output. The prompt used is structured as follows:

You are an expert in Semantic Web and Knowledge Graphs.
Your task is to generate RDF triples from the attached CSV data, exclusively using classes and properties present in the provided ontology.

Example triple 1
Subject: POI with ID POI_001 -> bo:POI_001
Predicate: bo:isUnderPortico
Object: Portico with ID Portico_023 -> bo:Portico_023
RDF Triple: bo:POI_001 bo:isUnderPortico bo:Portico_023 .

Example triple 2
Subject: Portico with ID Portico_023 -> bo:Portico_023
Predicate: bo:hostsPOI
Object: POI with ID POI_001 -> bo:POI_001
RDF Triple: bo:Portico_023 bo:hostsPOI bo:POI_001 .

Example triple 3
Subject: POI with ID POI_045 -> bo:POI_045
Predicate: bo:hasCoordinates
Object: "44.4949,11.3426"
RDF Triple: bo:POI_045 bo:hasCoordinates "44.4949,11.3426" .

Example triple 4
Subject: POI with ID POI_045 -> bo:POI_045
Predicate: bo:hasDistrict
Object: "Santo Stefano"
RDF Triple: bo:POI_045 bo:hasDistrict "Santo Stefano" .

Technique 3 — Zero-Shot Chain-of-Thought Prompting

In the zero-shot chain-of-thought technique, the model is instructed to reason explicitly and in a structured manner before producing the output, following a chain of thought defined in the prompt. No examples are provided, but the logical process to follow is specified:

You are an expert in Semantic Web and Knowledge Graphs.
Your task is to generate RDF triples (in Turtle syntax) from the data extracted from the file "df_POI 2.csv", exclusively using the classes and properties present in the ontology defined in the file "bologna_poi_corrected_2.ttl".

For each row of the CSV provided to you, you must reason and proceed step by step following this precise chain of thought (Chain-of-Thought):

1. SUBJECT AND CLASS IDENTIFICATION:
Analyze the value of "ID_univoco" and "Tipologia POI". What is the correct URI for the subject? What is the most specific ontology class (rdf:type) to assign to it?

2. PROPERTY EXTRACTION:
Examine each populated column. Which ontology property semantically fits this data? What is the correct data type for the Literal?

3. DOMAIN AND RANGE VERIFICATION:
Check that the Subject belongs to the correct rdfs:domain of the property and that the Object respects the rdfs:range.

Let's think step by step. Scan the entire provided CSV to identify all unique categories present in the Tipologia POI column.

Comparison of Performance Between LLMs

To evaluate the performance of the language models employed, a qualitative comparison was made between the outputs generated by Gemini Pro and ChatGPT Plus across the different adopted prompting configurations.

LLM Strengths Observed Limitations
Gemini Pro Structured and descriptive outputs, with detailed explanations of the mapping process between dataset and ontology. Good semantic interpretation capacity, high level of detail in explanations. Tendency to produce demonstrative rather than complete outputs. In some cases, it fails to identify all categories present in the dataset and introduces unsolicited interpretations.
ChatGPT Plus Outputs oriented towards the generation of RDF triples and the formalization of the ontological structure. Greater capacity to produce complete conversions of the dataset, good adherence to instructions. Lower level of detail in methodological explanations and less contextualization of the mapping process compared to Gemini Pro.
